# Canonical Freight terminal export: source and native qualification

The new terminal caller reads an explicit saved selection, obtains the existing native per-load bundles on its private captured view, and passes those exact tuples to the published `build_batch_bundle`. It publishes that producer's complete ZIP without clobbering a destination, then writes a separate capture receipt. The consumer does not contain an outer archive assembler or modify the shared format.

The original overlapping terminal offer is retained only as historical source/evidence. PR47 supplied the shared API and merged before this caller was authored. Root's continuation is [issue37 comment6064195824](https://github.com/Jacob-Met/workflow-checks/issues/37#issuecomment-6064195824). ## Delivery and custody limits

All request/selected-source/output admission precedes the no-clobber link. A source path/byte reread and absent-decisions check detect observed changes, without claiming a shared live-server lock, cross-process lease or hostile-parent race protection. Temporary capture and archive writes are confined to owned sibling staging. No existing source, destination winner or review is overwritten.

Archive publication precedes the stdout receipt. A later receipt-output failure does not roll back the delivered file and is not proof of no delivery. The new clean 2 handling and historical 120 result stay separate. A rare staging-cleanup failure after publication has an explicit already-published diagnostic; this branch was reviewed from source, not fault-injected in the recorded native runs. No original customer input, financial action, browser automation, installed service or external delivery is involved.

## Verify or reproduce without replacing evidence

`verify_packet.py` checks the published byte inventory, captured source images, raw native records, historical archives and independent manifests. It does not execute product code. Each nested packet retains its own verifier and frozen hashes. The top-level manifest excludes itself; the publication transaction binds that manifest's exact blob separately.

For a new execution, restore or copy the intended source into a fresh disposable directory and preserve all old evidence directories. The current package command is:

```sh
PYTHONDONTWRITEBYTECODE=1 python -B -m pytest -q -p no:cacheprovider
```

Run it from the restored `freight_packets` directory with pytest already available. `qualify.py` retains the historical unittest-composition runner and `qualify_shape.py` runs only the new regression against the stored raw R1 witness. They accept explicit candidate/output paths and create synthetic temporary files. In an environment without pytest, the historical full-discovery attempt may again report inherited import errors; do not mistake unittest discovery for collection of pytest function tests. The `pytest-recovery` receipt records the exact four-file command that closed that gap in this qualification.

Runtime versions and temporary paths in a new execution are new evidence. Never write a replay into the preserved `native-r1`, recovery, independent or historical directories, and never install the historical custom assembler over the published shared producer.
